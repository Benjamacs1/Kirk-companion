# Kirk Companion

An MIT-licensed desktop app that starts your existing Minecraft instance from the Kirk website. It stays in your system tray while Minecraft is closed. The setup window follows Kirk's Ghost and Kirk GUI palettes, with sidebar navigation and compact controls.

**Preview:** the desktop app is built and the complete flow is tested locally. The hosted Kirk dashboard/backend still needs the companion update deployed before public pairing works. Local launch tests work without pairing. [Windows preview releases](https://github.com/Benjamacs1/Kirk-companion/releases).

![Kirk Companion setup window](docs/setup.png)

## Use

1. Install Kirk Companion on the gaming PC.
2. Add a profile: select Prism/MultiMC and an instance, choose an instance shortcut generated by another launcher, or choose **Open launcher only**.
3. Use **Test launch**. Your launcher handles Minecraft login, Java, assets and mods. Kirk must already be installed in the selected instance.
4. On the Kirk dashboard, select **Pair a computer**. Enter the code and your PC's name in the companion.
5. Select your PC and profile on the dashboard and press **Start game**. This also works from a phone while the gaming PC is awake, signed in and the companion is running.

Closing the window keeps the app in the tray. Choose **Quit** in the tray to disconnect. Start on login is optional and available in the installed Windows/macOS app. Linux users can configure desktop autostart separately. The `kirk://open` link opens the setup window on the computer viewing the website; it never launches arbitrary URL arguments.

## Launcher support

| Method             | Behavior                                                                                                                                                                                |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Prism / MultiMC    | Runs the selected executable with `--launch <instance-folder-name>` and optional `--dir <data-folder>`. Detects instances in common data directories; Browse handles portable installs. |
| Instance shortcut  | Opens a local shortcut you select. Suitable for Modrinth or another launcher that generates an exact-instance shortcut. Verify it with Test launch.                                     |
| Open launcher only | Opens the selected launcher. You still choose an instance and press Play locally.                                                                                                       |

Compatibility depends on your launcher's installed version and ability to load Kirk's required Minecraft/Fabric version. A successful dispatch means the launcher accepted a process/open request, not that Minecraft authenticated or Kirk loaded. The dashboard's existing game connection reports when Kirk is actually online. A 30-second per-profile guard prevents rapid duplicate dispatches; it does not detect every launcher-managed running instance.

## Build from source

Requires Node.js 22.12+ and npm. No Kirk mod source, license key, Microsoft credentials or proprietary SDK is needed to build this app.

```sh
npm ci
npm test
npm start
```

Create a Windows installer and matching source archive:

```sh
npm run dist
```

Outputs `dist/Kirk Companion Setup 0.1.0.exe`, `dist/kirk-companion-0.1.0-source.zip`, and `dist/SHA256SUMS.txt`. Windows is the locally verified packaging target. macOS DMG and Linux AppImage targets are configured but require platform builds and integration testing. No signing certificate is bundled; local Windows installers are unsigned.

`npm run test:ui` drives the actual Electron app with a temporary data directory, a loopback backend and a tiny fake launcher. On Windows it uses the .NET Framework C# compiler included with Windows. It creates screenshots under `artifacts/` and never launches your real Minecraft installation.

## Architecture and privacy

- `src/main.mjs`: native window, tray, file dialogs, encrypted credential storage and narrow IPC.
- `src/service.mjs`: pairing, outbound WebSocket connection, expiring launch requests and duplicate prevention.
- `src/profiles.mjs`: profile validation, discovery and shell-free launcher invocation.
- `src/ui/`: local HTML/CSS/JS. Sandboxed with context isolation; no remote content, scripts or Node access.
- [Protocol and server integration](docs/protocol.md).

Only profile IDs, display names, launcher kinds and capabilities are sent to the server. Executable paths and arguments stay local. The companion never reads launcher account stores or Minecraft tokens. Its own pairing credential is encrypted with Electron's OS-backed `safeStorage`; if no secure store is available, it is kept only in memory until Quit. Unpair removes the local credential and attempts to revoke it server-side. You can also remove a PC from the dashboard.
